# OPERA decisions log

One line of reasoning per decision. Newest at the bottom.

| # | Decision | Reasoning |
|---|---|---|
| D1 | Frontend lives in `src/opera/` (not a new top-level dir). | Upstream's build, boundary and format tooling all treat `src/` as the browser runtime; matches the spec's proposed layout. Import-direction gate verified compatible (no Node/server/standalone imports). |
| D2 | OPERA gets the Cesium viewer from `window.__godsEyeView.viewer`, not by importing `src/standalone/*`. | The boundary gate forbids non-entry modules importing standalone setup; the debug handle is the documented stable shape. |
| D3 | One added line in `index.html` (`<script type="module" src="/src/opera/boot.js">`) is the only upstream frontend edit. | Smallest possible hook; keeps `src/main.js` untouched. Everything else is additive. |
| D4 | Node 24.22.0 is installed as a user-local tarball at `~/.opera-tools/node-v24.22.0-darwin-arm64` (SHA-256 verified); system Node is 22.20 and fails upstream's `engines` + allocation-budget tests. | Spec/README require Node 24.x. Local tarball avoids touching global installs. Activate with `export PATH=$HOME/.opera-tools/node-v24.22.0-darwin-arm64/bin:$PATH`. |
| D5 | Python venv built from Python 3.13 (`/opt/homebrew/bin/python3.13`), not the system 3.14. | Spec asks for 3.12+; torch/GeoCLIP wheels for 3.14 are unlikely to exist yet. |
| D6 | Vitest config in a separate `vitest.config.js` with `*.spec.js` files. | Vite config is an upstream re-export (don't edit); Vitest prefers `vitest.config.js`. `*.spec.js` avoids upstream's `*.test.mjs` node:test discovery. |
| D7 | OPERA's own dev port: Vite picks the first free port from 4173 (4173 is held by another local process on this machine; left untouched). Backend defaults to `127.0.0.1:8000`. CORS origins are configurable via `OPERA_CORS_ORIGINS`. | Spec: "CORS restricted to the Vite dev origin". Not killing processes I do not own. |
| D8 | `X-OPERA-Key` used from the browser is exposed as `VITE_OPERA_API_KEY`. It is a shared secret for local/dev, not per-user auth. | Spec mandates the header; documented as a limitation in PRIVACY.md. Real multi-user auth is out of scope for V1. |
| D9 | SQLite from the start; PostGIS only through `docker-compose.yml` (not run: Docker not installed). | Operator instruction. Candidate geometry is stored as lat/lon columns on SQLite and `geography(Point)` only when `DATABASE_URL` is PostgreSQL; the Postgres path is **untested** and will be labelled so. |
| D10 | Backend started with `uvicorn --factory app.main:create_app` (no module-level `app`). | Importing the module must not create the DB or upload directory; tests build apps from explicit settings. |
| D11 | Errors use FastAPI's `{"detail": "..."}` shape. | The M1 frontend client already reads `payload.detail`; no custom envelope needed. |
| D12 | Rate limit runs **before** the API-key check, keyed by salted hash of the client IP. | Throttles key guessing; health is never limited. In-memory and single-process only (documented limitation). |
| D13 | With no `OPERA_API_KEY` set, every non-health route answers 503 (fail closed) rather than running open. | Conservative: an unconfigured server must not accept uploads from anyone. |
| D14 | `metadata_free=false` is accepted but ignored (always stripped), with a response notice. | The spec lists the flag but no V1 feature needs original metadata; keeping GPS would only add privacy risk. |
| D15 | `uploads.deleted_at` exists (per spec Sec. 7) but is unused: DELETE and the sweeper hard-delete file and rows. | A soft delete would keep image-linked rows we promised to remove. |
| D16 | Early 413 uses `Content-Length` > `max_upload_bytes` + 1 MiB (multipart overhead). Chunked uploads without a length are still bounded by the byte cap after parse. | Starlette parses multipart before handlers run; the header check avoids spooling obviously huge bodies. |
| D17 | (Superseded by D18 in M3.) Until M3 lands a real runtime, `geoclip-v1` is registered as an `unavailable` adapter and `analyze` with it returns 503; `mock` must be requested explicitly. | Never silently substitute mock output for a real model. Candidate `uncertainty_km` is a per-band heuristic (`band-heuristic-v0`), not a measured error. |
| D18 | `geoclip-v1` is now a real adapter (GeoCLIP 1.2.3, local CPU/GPU). It is `unavailable` with a reason if torch/transformers/geoclip are missing; `analyze` with an unavailable model still returns 503 and never substitutes mock output. | D17's rule stays: no silent substitution for the candidate model. |
| D19 | Adapters use `kind: mock \| real` and the methods `predict(image_bytes, ...)` / `extract(image_bytes, ...)` rather than the spec's illustrative `mock \| clues \| geolocation` and `analyze(image_path)`. Role (clues vs geolocation) is the registry `role`. | Bytes in memory avoid temp files holding user images; one `kind` flag drives the MOCK badge. |
| D20 | When the real VLM is unavailable and clues are requested, the pipeline shows `mock-clues` (prefixed `MOCK:`, `clues_kind: "mock"`, notice naming the reason) rather than no clues. Candidates are unaffected and `model_kind` stays that of the geolocation model. | Spec Sec. M3: "UI shows clues as MOCK" when the key is unset. Replaces the earlier "no clues" behaviour; the old test was rewritten, not deleted, to assert the labelling. |
| D21 | VLM model default `gpt-6-luna`, prices 0.1 / 0.5 USD per 1M input / output tokens, taken from OpenAI's model docs on 2026-10-15; both in config, overridable by env. | Spec: pick a current vision model from the docs at build time; prices in config, not code. Not verified against the live API (no key). |
| D22 | The Structured Outputs schema (`VlmClueOutput`) has no `maxLength`/`default`/range keywords; limits (20 clues, 300 chars, 3 region guesses) are applied after parsing. A test walks the generated strict schema for banned keywords. | OpenAI strict mode rejects many keywords; offline tests cannot prove the live API accepts the schema, so the schema is kept as plain as possible. |
| D23 | VLM calls use `store=False`, a 30 s timeout and one SDK retry. A refusal produces a notice and no clues (it is not treated as "no geographic content"); only the model's own `abstain=true` can abstain the analysis, and only for real clues. Any API error becomes a notice containing the exception type name only. | Spec: do not fail the request on API errors; avoid leaking provider messages or key fragments into stored notices. |
| D24 | GeoCLIP's top-400 gallery points are thinned by greedy spatial non-maximum suppression at 50 km before taking five. Scores are passed through unchanged and never summed or averaged. | Raw top-5 gallery points are often neighbours of one place, which makes five "candidates" pointless. Radius is a UI-level choice, not tuned. |
| D25 | Band/abstention thresholds (`abstain_below_score=0.005`, `band_high_at=0.05`, `band_medium_at=0.015`) are provisional and read from config, chosen after seeing raw GeoCLIP scores of 0.0002-0.056 on ~8 Commons images. M5 calibration replaces them. The earlier placeholders (0.02/0.15/0.5) made every real answer abstain. | Honest placeholder; every candidate stays `uncalibrated: true`. |
| D26 | `build/vite.js` CSP `connect-src` gains `http://127.0.0.1:8000 http://localhost:8000`. | Found by running real mode in a browser: upstream's policy only allowed HTTPS/WSS, so the OPERA backend's default local address was blocked (mock mode never makes a request, so it hid this). Minimal widening to the two default origins; an HTTPS backend is already allowed. |
| D27 | `latency_ms.total` sums top-level stages only; `model_infer`/`model_load` are sub-stages of `geolocate` and are listed but not added again. | First real run reported total 20 s for a 10.7 s request. |
| D28 | Reverse geocoding goes through a `ContextProvider` interface with one implementation, `NominatimProvider`. Only model-predicted coordinates, rounded to 3 decimals (~110 m), are sent; the image, its hash and any metadata never are. | Privacy: the provider is a third party. Rounding also makes the cache effective. |
| D29 | Nominatim policy handling: identifying `User-Agent` from `OPERA_CONTEXT_USER_AGENT`, requests serialised under a lock with >=1.1 s spacing, 7-day LRU cache (2048 cells), 3 s timeout, up to 3 attempts with exponential backoff on timeouts/5xx, HTTP 403/429 never retried and start a 10-minute cooldown, 3 consecutive other failures start a 30 s cooldown. A stale cache entry is served (status `stale`) when the provider fails. | Spec M4 and the public usage policy. Cooldowns avoid hammering a service that has already refused us. |
| D30 | The default User-Agent is a placeholder that says to set a contact URL. **The owner must set `OPERA_CONTEXT_USER_AGENT` to a real app name plus contact before any non-local use.** No live request to the public Nominatim was made in this build. | A placeholder contact is not policy-compliant identification, so I did not send real traffic; E2E uses a local stub (`tests/opera/e2e/nominatim_stub.py`). |
| D31 | Enrichment has one 8 s per-analysis budget (`context_budget_s`). The first failure short-circuits the remaining candidates (marked `context.status: "unavailable"`) and adds one notice; the analysis stays `complete` with coordinates only. Candidates from the `mock` model are never sent to the provider. | Spec: "candidates still render with raw coordinates". A down provider must not multiply the wait by five; mock coordinates are not worth a third-party call. |
| D32 | OSM attribution ("© OpenStreetMap contributors") is added to `provenance` only when at least one place name was actually obtained, and then shown both in the candidates panel and as a static Cesium credit that is removed when the analysis is cleared. | Attribution is owed for data used, not claimed when nothing was used. |
| D33 | Existing dev SQLite files get the new nullable `candidates.context` column via `_add_missing_columns` at startup (idempotent, tested). Still no Alembic. | Keeps D-series "create_all" migration story honest without silently breaking an old database. |
| D34 | The optional country/admin boundary highlight and the Overture provider were **not built**. | Both are marked optional/time-permitting; boundaries need a polygon source whose licence and size I would have to vet, and M5 is larger. Logged as not done rather than half-done. |
| D35 | The OPERA panel and launcher use `z-index: 111` (was 60). Upstream right-rail panels live in `#right-context-rail` (z 110) and covered the Analyze button once the mode tabs pushed it down. OPERA now draws over that rail; upstream modals (175+) still sit above it. | Found by the pre-existing `mock-ui.mjs` E2E: a real user could not click Analyze. The test was not changed. |
| D36 | No Cesium labels in benchmark overlays: the upstream policy test forbids new Cesium labels, so the legend (truth / guess / model / context colours) lives in the panel text and markers carry only counter-based entity ids. | Respect an upstream gate rather than relax it. |
| D37 | Added endpoints beyond the spec contract: `GET /api/v1/evaluations` (list), and `GET /api/v1/benchmark/{datasets,rounds,images/...}` plus `POST /api/v1/benchmark/play`. Round responses carry no coordinates; truth arrives only in the `play` reply. Images are re-encoded without metadata. | The spec's game flow (metadata-free image, optional guess, reveal) needs a server contract and none was given; keeping truth server-side stops it leaking through the DOM or network tab before the guess. |
| D38 | Evaluation datasets live in `backend/fixtures/benchmark/<id>/` with the spec's manifest columns plus `split, continent, filename, image_url, sha256`. The dataset `version` is the first 12 hex chars of the manifest SHA-256; every image is hash-checked before use. | A changed image or manifest must change the version, or reproducibility claims mean nothing. |
| D39 | `opera-synthetic-v1` (8 generated PNGs, 4 seed + 4 heldout, committed) exists only to test the pipeline. It is labelled synthetic and must never be quoted as an accuracy number. | Spec fallback for tests when real images cannot be committed. |
| D40 | Leakage = exact SHA-256 match or perceptual-hash (pHash 64-bit) Hamming distance <= 6 between images in different splits; any finding fails the run with the pairs listed. Duplicates inside one split are allowed. | Only cross-split sharing invalidates a held-out test; 6/64 is a conservative near-duplicate bound I picked, not a tuned value. |
| D41 | Eval jobs run on a single-worker thread pool inside the API process (no external queue). Runs interrupted by a restart are marked `failed` at startup. Evaluation never uses mock clues; if the VLM is unavailable the run proceeds without clues and says so. | Single-user V1; a queue would add infrastructure for no benefit. Mock clues would silently change what is being measured. |
| D42 | `reproducible_hash` covers all metrics and slices except `ops` (latency and cost vary by machine). The GeoGuessr-style game score `5000*exp(-d/1492.7)` is shown only in the game and labelled a game score. | Same inputs must give the same hash; the game curve is not a research metric. |
| D43 | `AppContext` is now built by `build_context(settings)` in `main.py` so the CLI and API share wiring. | Needed for `python -m app.eval.cli`; behaviour unchanged (tests still pass). |
